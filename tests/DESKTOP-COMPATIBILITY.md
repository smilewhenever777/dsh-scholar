# 官方 DSH Desktop 兼容性审查

日期：2026-10-21。范围：学者工作台、服务器看板、研究主线图及三者使用的共享客户端代码。本说明对应“全面适配DSH桌面端”源码更新，不代表历史 v0.3.0 Release 或 npm 安装包已更新。

## 兼容方式

官方桌面端使用 Web 客户端运行时，页面来自 `dsh-app://app/`，宿主使用独立 `desktop` profile。插件的 `dsh.client.platform` 应继续声明 `web`，并通过官方 Web Host 转发访问原有路由。不能直接改成 `desktop`，也不应让客户端连接固定的 `localhost:3080`。

安装与重启方式见[仓库说明](../README.md#官方桌面端)。桌面程序、托盘生命周期和请求转发的上游依据见[官方 Desktop 文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/README.md)。本轮同时检查了本机 0.2.1-rc.2 安装包中的实际转发与新窗口策略。

## 本轮发现及修复

| 问题 | 影响 | 修复与验证 |
|---|---|---|
| 普通对象只附加 `meta.volatile` | 设置写入文件成功，原生 Loader 却不更新运行值；看板 revision 不变 | 三插件统一使用 `@deepseek-ai/schemastery` 的 `.volatile()`，读取原生引用；真实宿主验证立即读回，旧 revision 返回 409 |
| 当前会话仍按 `sessions.current` 读取 | 0.2 Controller 已移除该字段，可能选到另一个项目 | 优先使用 sidebar mounted 身份，随后使用唯一 mainView 所有权；保留旧 Web 选择形态，不以最近/首个工作区代替当前会话 |
| PDF/报告依赖新窗口 | 官方桌面拦截应用 URL 新窗口，打开无反应 | 仅拦截本插件的同源文档链接，在应用内预览；原报告 CSP sandbox 保持有效 |
| 三抽屉各自改宿主宽度 | 触发原生自适应侧栏收起，入口消失；同时展开时遮挡导航 | 统一布局所有权，保留宿主实际视口宽度；空间不足时其他面板收成窄栏；原生右栏和插件争抢空间时按最近操作互相让位；卸载最后一个所有者时恢复原布局 |
| 顶部避让累计内容工具栏高度，操作图标拥挤 | 面板上方空白、标题被截断 | 三插件仅避让原生标题栏；统一紧凑头部，次要窗口操作进入带文字菜单。Windows 实测从 80px 改为 40px，菜单验证键盘、Esc、外部点击和浮窗切换 |
| 浮窗和全页视图使用旧标题栏偏移 | 标题或拖拽区域进入原生窗口控制区 | 使用官方标题栏变量，几何尺寸检查有限数并夹取到可用视口 |
| 文件引用调用不存在的 `workspaces.openPath` | 无法显示位置，静默复制也无法得知结果 | 通过有权限声明的 `remote.session.openWorkspacePath` 显示位置；失败显示复制结果，键盘可操作；实际路径与显示路径一致 |
| 学者/主线设置加载失败仍可保存 | 初始空配置可能覆盖用户设置 | 配置成功加载后才允许保存，目录选择取消不改草稿 |
| 共享源码被 Git 忽略 | 本机可构建，新克隆缺少依赖源码 | 明确放行共享源码，随插件构建打入客户端包，无需单独安装共享包 |
| 看板临时快照进入候选文件 | 可能公开服务器与进程信息 | 保留本地文件并将 `dash_tmp.json` 加入忽略规则 |
| 共享请求助手覆盖调用方 signal | 卸载或切换后请求仍继续 | 合并调用方取消与超时信号，保留 HTTP 错误状态及业务码 |
| 对话指令交付依赖旧 DOM 空白判断 | 原生富文本结构变化后只能复制，无法稳定填入当前会话 | 优先使用宿主会话输入接口，仅填入空白且未提交的输入；保留草稿、附件及手动发送步骤 |
| GET 浏览器请求可能没有 Origin | 外站仍可能触发本机读取或 SSH 采集 | 三插件补充 Fetch Metadata 校验，拒绝 cross-site/same-site 请求；保留原有 Host、Origin 与 loopback 检查 |

## 验证

1. 三插件宿主及客户端类型检查、构建通过。完整仓库既有回归通过，包含论文、存储、路由、凭据兼容、配置契约和窄栏滚动。
2. `desktop-contract.test.mjs` 的 13 个用例覆盖原生 volatile 引用、SettingsForms 读写、当前会话归属、路径规范化、原生文件动作与失败兜底、目录选择取消、请求取消、损坏浮窗几何和对话输入保护。`browser-trust.mjs` 另有 12 项断言验证跨站请求被拒及官方转发形态可用。
3. `desktop-installed.mjs` 在 Windows 官方 DSH Desktop **0.2.1-rc.2** 实际启动独立应用与宿主，使用独立 `DSH_HOME`、Electron 用户目录和合成库。15 组检查验证三个真实 bundle 加载、三设置读回、过期配置拒绝、不发消息切换工作区、PDF 预览、报告脚本沙箱、多抽屉入口可见、原生输入填入与草稿保护、三个原生右栏页及空间让位、顶部对齐和次要操作菜单，以及 Markdown 下载落盘。页面未出现未处理异常。
4. 三插件公开范围检查通过：当前候选源码、常见敏感信息模式、相对文档链接、npm 包清单。共享源码编译进各插件 bundle，不要求运行时访问仓库相邻目录。
5. 使用桌面安装包自带 CLI，在已初始化且退出的隔离 profile 中，三个含空格绝对路径的 `link:` 安装命令均通过。
6. 更新三个开发锁文件中的 `compression` 到修复版本 1.8.2。原锁定版本命中[上游内存泄漏拒绝服务公告](https://github.com/advisories/GHSA-vc2v-76pw-4v95)；本机官方桌面安装包自带版本已是 1.8.2，未修改桌面安装文件。
7. 统一界面在 300、440、900px 的明暗主题下共 18 项视觉检查通过；分区保持在左，统计条及输入框不横向溢出。桌面默认面板不再固定预留 1100px，按原生导航和对话区计算可读宽度。
8. 三插件最终依赖审计均为 0 个已知漏洞。公开文件复制到干净目录后重新安装、构建并回归；后续右栏布局调整追加了真实桌面验收和干净构建核对。

复现命令和环境变量见[测试说明](./README.md)。实际桌面测试保留截图、下载文件和 JSON 结果在忽略目录 `.verify/` 中；不把运行数据或真实凭据放入公开包。

## 范围与剩余事项

- 原生目录选择和文件定位的服务调用、取消及失败用隔离替身验证；未自动操作真实文件管理器窗口或让系统选择器改动用户目录。
- SSH、模型和凭据生命周期的回归使用隔离服务；本轮没有访问用户真实 GPU 主机或发送真实论文给模型，不以合成测试代替这些环境的验收。
- macOS 标题栏变量保留兼容路径，尚未在 macOS 真机测试；Windows 桌面验证不能推导所有桌面版本均兼容。
- 本次公开检查覆盖三个插件、共享客户端、相关测试和待提交文件；其他插件应另行构建和审查。
